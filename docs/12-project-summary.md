# Project Summary — Wazuh Home SOC Lab

## Overview

This project involved building a functional **Home Security Operations Center (SOC)** lab using **Wazuh, Windows, Ubuntu, and Sysmon**.

The objective was to gain hands-on experience with endpoint monitoring, security event analysis, threat hunting, detection engineering, MITRE ATT&CK mapping, attack simulation, and automated incident response.

A Windows endpoint was monitored using the Wazuh agent and Sysmon, while an Ubuntu virtual machine hosted the Wazuh manager.

The completed lab demonstrates an end-to-end security monitoring workflow:

```text
Windows Endpoint
      ↓
Sysmon Telemetry
      ↓
Wazuh Agent
      ↓
Wazuh Manager
      ↓
Detection & Alerting
      ↓
Threat Investigation
      ↓
MITRE ATT&CK Mapping
      ↓
Active Response
```

## Key Implementations

### 1. Wazuh Agent Monitoring

A Windows endpoint was connected to the Wazuh manager using the Wazuh agent.

The agent provided centralized visibility into security events generated by the endpoint.

Monitored endpoint:

```text
SP-WIN-01
```

This established the basic endpoint-to-SOC monitoring pipeline.

---

### 2. File Integrity Monitoring

Wazuh File Integrity Monitoring (FIM) was used to monitor changes to selected files and directories.

This provided visibility into filesystem activity and demonstrated how a SOC can detect potentially unauthorized file modifications.

The implementation covered:

- File creation
- File modification
- File deletion
- Integrity monitoring alerts

---

### 3. Sysmon Integration

Microsoft Sysmon was installed and integrated with the Wazuh agent.

The Sysmon Operational event channel was configured for collection by Wazuh.

This provided detailed endpoint telemetry, particularly for process creation events.

Sysmon Process Creation events were successfully received and analyzed by Wazuh.

```text
Sysmon Event ID 1
        ↓
Wazuh Agent
        ↓
Wazuh Manager
        ↓
Security Alert
```

---

### 4. Threat Hunting

Wazuh events were investigated through the dashboard to understand endpoint activity and distinguish potentially suspicious behavior from normal system activity.

Threat-hunting activities included examining:

- Process execution
- Command-line activity
- Parent-child process relationships
- Windows authentication activity
- Sysmon telemetry
- Security alerts

The investigation also demonstrated the importance of identifying false positives and distinguishing legitimate software activity from suspicious behavior.

---

### 5. Custom Detection Engineering

A custom Wazuh detection rule was created to identify the execution of Windows Notepad.

Custom rule:

```text
Rule ID: 100100
Rule Level: 5
Description: Custom Detection: Notepad process created
```

The rule analyzes Sysmon Process Creation events and detects:

```text
notepad.exe
```

Testing confirmed the complete detection pipeline:

```text
Notepad.exe
      ↓
Sysmon Event ID 1
      ↓
Wazuh Agent
      ↓
Custom Rule 100100
      ↓
Wazuh Alert
```

This demonstrated practical experience with custom detection rule creation and validation.

---

## Attack Simulation

Benign attack simulations were performed on the Windows endpoint to generate realistic security telemetry.

Discovery commands included:

```cmd
net user
whoami
net user guest
```

These commands were used only for controlled lab testing.

Wazuh successfully detected the resulting activity.

One notable detection was:

```text
Rule ID: 92039
Command: net user guest
```

This demonstrated how endpoint discovery activity can be identified through process and command-line telemetry.

---

## MITRE ATT&CK Mapping

Detected activity was analyzed in the context of the **MITRE ATT&CK framework**.

The account discovery simulation demonstrated how SOC alerts can be connected to attacker tactics and techniques.

This provided experience moving beyond individual alerts and interpreting activity according to established threat-behavior frameworks.

---

## False Positive Analysis

Not every security alert observed during the project represented malicious activity.

Examples of legitimate activity investigated included:

- Windows update activity
- Microsoft Defender activity
- Adobe-related processes

Process paths, parent processes, command lines, and surrounding event context were examined before determining whether an alert represented suspicious activity.

This demonstrated an important SOC analyst skill:

> An alert is an investigation starting point, not automatic proof of malicious activity.

---

## Active Response

A custom **stateful Wazuh Active Response** was implemented as the final phase of the project.

For safety, destructive response mechanisms such as firewall blocking, account disabling, or network route modification were intentionally avoided.

Instead, a harmless Python Active Response script was executed only on the Ubuntu Wazuh manager.

The response was linked to:

```text
Rule ID: 100100
```

When Notepad was detected:

```text
Notepad.exe
      ↓
Sysmon Event ID 1
      ↓
Custom Rule 100100
      ↓
Wazuh Active Response
      ↓
Custom Python Script
      ↓
Temporary Marker Created
```

The response created:

```text
/tmp/wazuh-active-response-test.txt
```

The marker contained confirmation that Rule `100100` triggered the response.

---

## Stateful Response and Automatic Rollback

The Active Response was configured with a **30-second timeout**.

After the timeout expired, Wazuh automatically executed the rollback action and the temporary marker was removed.

```text
Detection
    ↓
Active Response
    ↓
Marker Created
    ↓
30-Second Timeout
    ↓
Automatic Delete Action
    ↓
Marker Removed
```

This successfully demonstrated both automated response execution and stateful rollback.

After validation and documentation, the test Active Response was disabled so that normal endpoint activity would no longer trigger the automated test action.

The custom detection rule remained operational.

## Key Takeaways

This project demonstrated that building a SOC involves more than simply generating alerts.

The complete workflow requires:

1. Collecting useful endpoint telemetry.
2. Understanding normal system behavior.
3. Identifying suspicious activity.
4. Investigating alerts using contextual information.
5. Developing and testing detection rules.
6. Mapping observed behavior to threat frameworks.
7. Distinguishing false positives from genuine suspicious activity.
8. Validating detections through controlled simulations.
9. Implementing safe automated response mechanisms.
10. Verifying that automated actions can be rolled back successfully.

The Home SOC lab successfully demonstrated an end-to-end detection and response workflow using Wazuh and Sysmon.

```text

   ↓
Alert
   ↓
Investigation
   ↓
```

The completed project demonstrates practical foundational skills relevant to **SOC Analyst, Cybersecurity Analyst, Security Operations, and Blue Team roles**.
